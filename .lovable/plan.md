
# Plan: End-to-End Request Tracing for All SAP Flows

Goal: every SAP-touching request can be traced from browser click → edge function → Node middleware → SAP and back, correlated by a single `reqId`. No business logic, no auth changes, no request/response shape changes — only structured logging.

## Scope (all request paths to SAP)

Edge functions that talk to SAP directly or via the middleware:
- `supabase/functions/fetch-tenants-from-sap/index.ts` (already instrumented — keep, minor cleanup)
- `supabase/functions/sap-api-test-connection/index.ts`
- `supabase/functions/sap-master-fetch/index.ts`
- `supabase/functions/sync-vendor-to-sap/index.ts`
- `supabase/functions/sync-vendor-to-dms/index.ts`
- `supabase/functions/sync-vendors-to-sap-bulk/index.ts`
- `supabase/functions/prepare-dms-payload/index.ts`
- `supabase/functions/dynamic-api-executor/index.ts`

Middleware:
- `middleware/server.js` — extend the existing tracer to cover every route (`/sap/proxy`, `/sap/bp/create`, `/sap/dms/upload`, `/health`, and any catch-all).

Frontend (SAP-invoking surfaces only):
- `src/hooks/useSapApiConfigs.tsx`
- `src/hooks/useSapMasterData.tsx`
- `src/components/sap/*` (test-connection, multiple-sync dialog, master data tab, payload uploader)
- `src/pages/SAPSync.tsx`, `src/pages/SapApiSettings.tsx`, `src/pages/SapApiConfigEdit.tsx`
- `src/components/admin/AssignTenantDialog.tsx` (calls fetch-tenants)

## Shared tracing contract

- `reqId`: UUID, generated by the frontend at the call site (`crypto.randomUUID()`), passed to the edge function as `x-request-id`, forwarded to the middleware as `x-request-id`, echoed back in response headers.
- Log line format (all layers): single-line JSON with `{ svc, reqId, stage, ts, ...fields }`.
- Standard stages per layer: `req.received`, `auth.ok`/`auth.failed`, `body.parsed`, `config.loaded`, `upstream.prepared`, `upstream.fetch.start`, `upstream.fetch.end` (status, elapsedMs, headerKeys, bodyPreview ≤500B), `upstream.fetch.error` (name, code, cause, aborted, stack), `response.sent` (status, elapsedTotalMs).
- Frontend: `console.info` / `console.error` with the same `reqId` at: invoke.start, invoke.end (status + ms), invoke.error (message + stack).

## Masking rules (unchanged)

- Never print full values of: `Authorization`, `apikey`, `x-middleware-key`, `proxy_secret`, `password*`, `*token*`, `*secret*`, `service_role`, `password_encrypted`.
- Log only the **keys** present and `present: true/false` for secrets.
- Body previews capped at 500 bytes and run through a deep masker that redacts the keys above.

## Files to change

### 1. New shared helper (edge): `supabase/functions/_shared/trace.ts`
- `makeReqId(req)`, `trace(reqId, svc, stage, fields)`, `headerKeys(h)`, `maskHeaders(h)`, `maskBody(obj)`, `safePreview(text, n=500)`, `summarizeError(e)`.
- Used by every edge function in scope. Output identical JSON shape so a single `grep <reqId>` works.

### 2. Edge functions (8 files)
For each function:
- Generate/accept `reqId` at entry; log `req.received` with method, url, header keys.
- Log auth result, parsed body keys (masked), loaded config id + flags.
- Wrap every outbound `fetch` (to middleware or directly to SAP) with `upstream.fetch.start` / `upstream.fetch.end` / `upstream.fetch.error`, including elapsedMs, status, header keys, masked body preview, and on error: `name`, `message`, `cause.code`, `aborted`, full `stack`.
- Forward `x-request-id` on every middleware call.
- Final `response.sent` with `elapsedTotalMs` and outcome.
- `unhandled.error` catch-all with stack.
- No changes to request/response payloads.

### 3. Middleware — `middleware/server.js`
- Extract `reqId` middleware (already partly present) — apply globally via `app.use`.
- Per-route logger covering `/sap/proxy`, `/sap/bp/create`, `/sap/dms/upload`, `/health`, fallback 404.
- Log: `req.received` (ip, headerKeys, middlewareKeyPresent), `auth.result`, for each upstream call `upstream.prepared` (SAP url, method, headerKeys, username, payloadBytes), `upstream.fetch.start`, `upstream.fetch.end` (status, elapsedMs, responseHeaderKeys, bodyPreview ≤500B), `upstream.fetch.error` (name, code, cause, mapped describeFetchError, stack), `response.sent` (status, elapsedTotalMs).
- Echo `x-request-id` in response headers on every route.
- Reuse existing masker; extend to mask `password`, `*token*`, `*secret*`, `Authorization` deeply.

### 4. Frontend SAP call sites
- Add a tiny helper `src/lib/sapTrace.ts` exporting `withReqId()` and `logInvoke(reqId, fn, ms, status, error?)`.
- At each `supabase.functions.invoke(...)` call to a SAP function:
  - Generate `reqId`, pass via `headers: { 'x-request-id': reqId }`.
  - `console.info({ reqId, fn, stage: 'invoke.start', ts, bodyKeys })`.
  - On settle: `console.info({ reqId, fn, stage: 'invoke.end', elapsedMs, ok })`.
  - On throw: `console.error({ reqId, fn, stage: 'invoke.error', elapsedMs, message, stack })`.
- No UI/UX or business behavior changes.

### 5. Docs — extend `docs/TRACING_FETCH_TENANTS.md`
- Rename to `docs/TRACING_SAP_REQUESTS.md` (or add a new general doc) describing the new shared format, the helper, the masking rules, and grep recipes for all 8 functions plus middleware.
- Keep the existing nginx/Kong/edge-runtime tuning notes.

## Out of scope

- No changes to: authentication, RLS, request/response JSON shapes, SAP payload building, retry behavior, timeouts (other than the existing 110 s cap already in `fetch-tenants-from-sap`), nginx/Kong/docker configs (still documented, not edited).
- No new dependencies.

## Verification after build mode

1. Trigger one tenant fetch, one master-data fetch, one vendor sync, one DMS upload from the UI.
2. For each: copy `reqId` from browser console, then:
   - `docker compose logs --since=10m functions | grep <reqId>`
   - `journalctl -u vms-middleware --since "10 min ago" | grep <reqId>`
3. Confirm every layer logs the same `reqId`, all four lifecycle stages appear, and on a forced failure the `upstream.fetch.error` line carries `name`, `cause.code`, `aborted`, full `stack`.
4. Confirm no secret values appear anywhere in the logs (grep for known secret substrings — should return nothing).
